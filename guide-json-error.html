JSON 格式错误怎么办

2026-11-25 · 约 565 字

"Unexpected token"、"Unexpected end of JSON input"——JSON 解析报错几乎都是同一个原因：它比 JavaScript 对象严格得多，少一个引号、多一个逗号就会整个失败。

JSON 到底有多严格

JSON 是一种数据交换格式，规则很少但没有商量余地：

  • key 和字符串值必须用双引号，单引号不行
  • 不能有注释（// 和 /* */ 都不行）
  • 不能有尾逗号——最后一个元素后面不能加逗号
  • 只能有对象、数组、字符串、数字、true/false/null 这些类型
  • 数字不能带前导零，也不能写成 .5（要写 0.5）

这些在 JavaScript 对象里很多都是允许的，所以从代码里"照抄"一段到 JSON 文件，经常就报错。

五类最常见的错误

  1. 末尾多逗号：{"a":1,"b":2,}。这是头号杀手，写 JS 对象养成的习惯。去掉最后一个逗号。
  2. 用了单引号：{'a':1}。JSON 只认双引号，全部换掉。
  3. key 没加引号：{a:1}。在 JS 里合法，在 JSON 里非法。
  4. 混进了注释：JSON 不支持注释。如果配置需要注释，意识着那是 JSONC 或 YAML，不是纯 JSON。
  5. 中文标点：冒号写成了全角 ：，逗号写成 ，，引号写成 "。从网页或 Word 复制内容时极易带入。全部换成半角。

怎么快速定位

报错信息里通常带一个数字，比如 position 247，指的是出错字符在整个字符串里的位置。可以写一小段代码截取附近内容看看：

const s = '你的 JSON 字符串';
const pos = 247;
console.log(s.slice(pos - 30, pos + 30));

更省事的办法是把 JSON 粘贴进格式化工具——好的工具会直接标出出错的行和列，有的还会给出具体原因。格式化通过后，顺手就能看清结构，一举两得。

一个特别隐蔽的情况

从 Excel 或聊天软件复制的 JSON，看起来完全正确，却一直报错。多半是混进了不可见字符：零宽空格、BOM 头、不换行空格（ ）。肉眼看不出来，逐字符检查才能发现。遇到"看着没错就是报错"，试着重新手敲一遍关键部分，或者用工具清理不可见字符。

一句话：JSON 报错先查四样——末尾逗号、单引号、没引号的 key、中文标点。报错带 position 数字时，截那段字符串看看；看着没错却报错，多半是不可见字符。
