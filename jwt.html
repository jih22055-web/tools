JWT（JSON Web Token）是前后端身份认证最常用的令牌格式。这个工具把你粘贴的 Token 拆开，格式化显示 Header 头和 Payload 载荷，并把 exp 过期时间翻译成可读日期——全程在本地浏览器完成，Token 不会上传。

JWT 的三段结构

一个 JWT 由三段用英文句点 . 连接：Header（头部，说明算法和类型）、Payload（载荷，存放用户 ID、过期时间等声明）、Signature（签名，用于校验完整性）。前两段只是 Base64URL 编码，不是加密——任何人都能解码查看，所以千万别在 Payload 里放密码等敏感信息。

为什么要解码 JWT

调试登录问题时，经常需要确认 Token 里到底带了哪些信息、用户 ID 对不对、有没有过期、用的什么算法。把 Token 粘进来一秒解析，比在控制台手敲 Base64 解码快得多。

适用场景

  • 调试登录接口，查看 Token 里的用户 ID 和权限字段
  • 确认 Token 是否已经过期、什么时候过期
  • 排查前后端算法不一致（HS256 / RS256）的问题
  • 教学演示 JWT 的结构

使用方法

  1. 从浏览器 Cookie、localStorage 或请求头里复制完整 Token
  2. 粘贴到输入框，工具自动解析
  3. 查看 Header 和格式化后的 Payload，底部会标出过期时间

常见问题

解码 JWT 安全吗？会不会泄露？

本工具完全在浏览器本地解析，Token 不会发送到任何服务器。但要注意：JWT 的 Payload 本身是明文编码，任何拿到 Token 的人都能解出内容，这是 JWT 的设计如此，不是本工具的问题。

为什么 Payload 能直接读出来？

因为 JWT 只用 Base64URL 编码而非加密。编码是为了在 URL 和请求头里安全传输，不是保密。敏感数据不该放进 Token。

能验证签名是否正确吗？

本工具做结构解析和展示，签名校验需要服务端的密钥（HS256）或公钥（RS256），密钥绝不能暴露在前端，所以校验应在后端完成。
