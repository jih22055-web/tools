校验文件完整性：对比下载前后是否一致

2026-11-25 · 约 654 字

下载的系统镜像、软件包、驱动，动辄几个 GB。传到一半断了、网络出错、甚至被恶意替换，光看文件名根本发现不了。算一下哈希值，和官网给出的对比，是最可靠的确认方法。

校验的原理

哈希算法能把任意大小的文件算成一串固定长度的"指纹"（比如 32 位的 MD5 或 64 位的 SHA-256）。文件内容哪怕只改动一个字节，算出来的指纹也完全不同。所以只要下载后的指纹和官网公布的完全一致，就能确认：

  • 文件在传输中没有损坏（没丢包、没截断）
  • 文件和官网提供的是同一个（没被中间人替换）

操作步骤

  1. 找到官网公布的校验值。正规软件下载页会提供 MD5、SHA256 或 SHA1 的校验文件，通常在下载链接旁边，文件名类似 SHA256SUMS 或 xxx.md5。
  2. 下载完文件后，本地计算哈希。用命令行（Windows 用 certutil -hashfile 文件名 SHA256，Linux/macOS 用 sha256sum 文件名），或者用在线哈希计算工具把文件拖进去。
  3. 逐字符对比两个值。完全一致就没问题；不一样就说明文件损坏或被替换，不要用，重新下载。

用哪种算法

  • 只要防传坏（下载中断、U 盘坏道）：MD5 够用，快且通用
  • 要防恶意替换：用 SHA-256，MD5 已经被证明可以人为构造碰撞，攻击者能做出一个 MD5 相同但内容不同的恶意文件
  • 官网同时给了多个值，优先用 SHA-256

一个容易被忽略的前提

校验值本身必须来自可信渠道。如果你从某个论坛下载文件，校验值也来自同一个论坛，那攻击者完全可以同时替换文件和校验值，校验就成了摆设。正确做法是从软件官方 HTTPS 页面获取校验值，最好还能核对官方的数字签名。

大文件怎么算得快

几个 GB 的文件算 SHA-256 可能要几十秒到几分钟，这是正常的——算法要把整个文件读一遍。命令行工具通常比网页工具快，因为不需要先上传（网页工具如果是在浏览器本地算，也不上传，但受浏览器性能限制）。如果网页工具声称"上传后计算"，大文件就别用，既慢又泄露文件。

一句话：下载后算哈希、和官网公布的校验值逐字符对比，一致才算可信。防损坏用 MD5 就行，防替换必须用 SHA-256，而且校验值本身要从官方渠道拿。
