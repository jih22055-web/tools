301 和 302 有什么区别

2026-11-25 · 约 614 字

网站改版换了网址，旧链接不能直接删——用户书签、外部引用、搜索引擎索引里全是旧地址。这时候要做重定向。但 301 和 302 选错，轻则排名白丢，重则页面从搜索结果里消失。

一个"永久"，一个"临时"

301 Moved Permanently 告诉浏览器和搜索引擎：这个页面永久搬家了，以后请用新地址。302 Found（旧称 Moved Temporarily）则说：只是暂时去一下新地址，过段时间还会回来。

搜索引擎对两者的处理完全不同：

  • 遇到 301，搜索引擎会把旧 URL 的权重、外链价值逐步转移到新 URL，并把索引里的旧地址替换掉
  • 遇到 302，搜索引擎认为旧地址才是正式的，权重留在原地，新地址一般不会被收录

用错的典型后果

最常见的错误是页面真的永久改了地址，却图省事用了 302。结果新页面一直没排名，旧页面随着时间推移也没了权重，两头落空。反过来也有问题：临时活动页用了 301，等活动结束换回原内容，搜索引擎已经把旧地址从索引里删了，流量要很久才恢复。

308 和 307 又是什么

传统 301/302 有个副作用：重定向时浏览器可能把 POST 请求改成 GET，导致表单数据丢失。后来补充了两个更严格的状态码：

  • 308 Permanent Redirect：永久重定向，且保持请求方法和请求体不变
  • 307 Temporary Redirect：临时重定向，同样保持请求方法

做 API 迁移、表单接口跳转时应该用 308/307，普通网页跳转用 301/302 就够了。

怎么选

  • 换域名、改 URL 结构、HTTP 改 HTTPS → 301（或 308）
  • 临时维护页、A/B 测试、活动页、按地区跳转 → 302（或 307）
  • 多个域名指向同一个主站 → 301 到主域名
  • 带 www 和不带 www 的统一 → 301 到其中一个

三个容易被忽略的细节

  1. 301 会被浏览器长期缓存。改错了想改回来很麻烦，用户可能一直访问缓存里的旧目标。所以永久跳转上线前一定要想清楚。
  2. 重定向链要尽量短。A→B→C 会让权重在每一跳衰减，也拖慢加载。直接 A→C。
  3. 别用 JavaScript 的 location.href 代替服务端 301。搜索引擎对 JS 跳转的识别远不如 HTTP 状态码可靠。

一句话：永久搬家用 301，临时借用用 302。做接口跳转用 308/307 保住 POST 数据。选错了最直接的代价就是搜索排名归零。
