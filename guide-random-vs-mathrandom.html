Math.random() 和密码学随机数有什么区别

2026-11-25 · 约 581 字

用 Math.random() 生成了一个"随机"密码，看起来挺乱。但它在密码学意义上一点都不安全——攻击者只要观察到几个输出，就可能推算出后续所有结果。

伪随机：看起来随机，其实可推算

Math.random() 生成的是伪随机数（PRNG）。它内部维护一个"种子"，每次调用用固定公式算出下一个数。同样的种子永远产生同样的序列。这个公式是公开的，所以只要推断出种子，整条序列都能还原。

浏览器里的 Math.random() 用的是 xorshift128+ 之类的算法，速度极快，但设计目标是"统计上够随机"，不是"攻击者推不出来"。它适合做动画抖动、游戏里的普通掉落、随机背景色这类无关安全的场景。

密码学安全随机：不可预测

密码学安全伪随机数生成器（CSPRNG）从操作系统收集熵——鼠标移动、键盘时序、硬件噪声等——作为种子，并且设计上保证：即使知道之前所有输出，也无法预测下一个。浏览器里用它要调 crypto.getRandomValues()：

const arr = new Uint32Array(1);
crypto.getRandomValues(arr);
console.log(arr[0]); // 密码学安全的随机整数

Node.js 里对应的是 crypto.randomBytes()。要生成密码、会话令牌、验证码、CSRF token、API key，必须用这一类。

第二个坑：取模造成的分布不均

即使换成安全随机源，写法不对也会出问题。常见的 random() % 10 想生成 0 到 9，如果随机数是 0 到 4294967295 的 32 位整数，这个范围不能被 10 整除，前面几个数字出现的概率会比后面略高。差别很小，但在密码学和抽奖里，任何偏差都是缺陷。

正确做法是拒绝采样：算出能被整除的最大范围，超出这个范围的样本直接丢掉重抽。浏览器原生 API 通常已经处理好了。

怎么选

  • 动画、视觉效果、游戏普通逻辑 → Math.random() 没问题，还更快
  • 密码、令牌、验证码、抽奖、任何有"不能被人猜到"要求的场景 → crypto.getRandomValues() 或 crypto.randomBytes()
  • 需要一个现成的随机字符串 → 用在线生成工具，但要确认它明确说明用了浏览器或系统的安全随机源

一句话：Math.random() 快但可推算，只能用于"看起来随机"的场合；凡是涉及安全，一律换成 crypto.getRandomValues()。
